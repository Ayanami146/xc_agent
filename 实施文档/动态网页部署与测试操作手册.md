# 信创智能客服动态网页部署与测试操作手册

> 本文是偏生产环境的完整手册。如果只是 Windows 本机练习，请直接使用仓库根目录的《前端简单上线流程》，不需要部署本文列出的全部基础设施。

版本：v1.0（2026-08-25）  
执行人：实施/测试人员  
说明：本文只提供操作流程；编写阶段未连接服务器、未发布、未执行系统测试。

## 1. 交付边界和前置条件

当前仓库交付 Vue 用户端源码、API 对接层、接口契约、SSE Schema、端口流程和 Nginx 配置。仓库中没有 Java 业务服务、Python AI 服务、MySQL DDL 或生产密钥；上线前必须由相应后端服务实现并通过 `接口文档/openapi.yaml` 契约验证。只有 Nginx 和前端文件、没有业务 API 时，页面可打开但无法真实登录和使用动态功能。

准备以下信息：

- Linux 服务器、sudo 权限和业务域名，例如 `support.example.com`。
- 域名已解析到服务器/LB；443 入站已放行。
- 有效 TLS 证书和私钥。
- Java API 已在内网 `127.0.0.1:8080` 或指定地址运行。
- Python AI、MySQL、Redis、Qdrant、MinIO 已按《各端端口与调用流程》仅在内网开放。
- 一套普通测试账号、一套 MFA 管理测试账号、允许上传的测试文件和应被拦截的测试文件。
- 服务器时间同步正常；Java/Python 时差小于 5 分钟。

以下命令以 Ubuntu/Debian、站点目录 `/srv/xinchuang/frontend` 为例。RHEL/统信/麒麟环境请替换包管理器，但目录、验证顺序和 Nginx 语义保持一致。

## 2. 发布前契约检查

1. 用 Swagger Editor、Redocly 或团队的 OpenAPI 校验器打开 `接口文档/openapi.yaml`，确认无解析错误。
2. 后端导出的 OpenAPI 与本文件比较，禁止路径、方法、必填字段、枚举或响应信封不一致。
3. 用 JSON Schema 校验器加载 `sse-events.schema.json`，以真实后端保存的一组 SSE 事件逐条验证。
4. 核对后端响应 Content-Type：普通成功响应 `application/json`，错误建议 `application/problem+json`，流式响应 `text/event-stream`。
5. 核对服务器不会把内部 `/internal/**` 或 `/actuator/**` 暴露给公网。

## 3. 本地前端联调

进入 `frontend`，复制环境文件：

```bash
cp .env.example .env.local
```

编辑 `.env.local`：

```dotenv
VITE_API_MODE=remote
VITE_API_BASE_URL=/api/v1
VITE_API_PROXY_TARGET=http://127.0.0.1:8080
```

安装、启动：

```bash
npm ci
npm run dev
```

浏览器打开终端显示的地址。依次检查登录、会话、问答、FAQ/手册和工单。Vite 将 `/api` 代理到 `VITE_API_PROXY_TARGET`，前端代码仍使用同源路径。

如果只验证视觉页面，可另开终端执行：

```bash
npm run dev -- --mode mock
```

mock 不是后端验收结果，不能作为上线依据。

## 4. 构建生产文件

确认生产环境不含 `VITE_API_PROXY_TARGET` 也可正常构建；生产 API 保持同源：

```bash
cp .env.example .env.production.local
```

将 `.env.production.local` 内容改为：

```dotenv
VITE_API_MODE=remote
VITE_API_BASE_URL=/api/v1
```

执行：

```bash
npm ci
npm run build
```

构建成功后检查：

```bash
find dist -maxdepth 2 -type f -print
grep -R "VITE_API_PROXY_TARGET\|XinChuang@2026" dist || true
```

预期存在 `dist/index.html` 和带 hash 的 `dist/assets/*`；第二条命令不得找到开发代理地址或演示密码。

可在发布包外生成校验文件：

```bash
find dist -type f -print0 | sort -z | xargs -0 sha256sum > frontend-dist.sha256
```

## 5. 安装和准备 Nginx

安装 Nginx：

```bash
sudo apt-get update
sudo apt-get install -y nginx
```

创建版本目录。`RELEASE_ID` 建议使用 UTC 时间，例如 `20260825T020000Z`：

```bash
export RELEASE_ID=20260825T020000Z
sudo install -d -m 0755 "/srv/xinchuang/frontend/releases/$RELEASE_ID"
sudo cp -a dist/. "/srv/xinchuang/frontend/releases/$RELEASE_ID/"
sudo chown -R root:root "/srv/xinchuang/frontend/releases/$RELEASE_ID"
sudo find "/srv/xinchuang/frontend/releases/$RELEASE_ID" -type d -exec chmod 0755 {} \;
sudo find "/srv/xinchuang/frontend/releases/$RELEASE_ID" -type f -exec chmod 0644 {} \;
```

证书示例目录：

```bash
sudo install -d -m 0700 /etc/nginx/tls
sudo install -m 0644 fullchain.pem /etc/nginx/tls/fullchain.pem
sudo install -m 0600 privkey.pem /etc/nginx/tls/privkey.pem
```

将仓库 `deploy/nginx/xinchuang.conf` 复制到 `/etc/nginx/conf.d/xinchuang.conf`，修改：

- `support.example.com` 为真实域名。
- `ssl_certificate` 和 `ssl_certificate_key` 为真实路径。
- `upstream` 地址为 Java 服务内网地址；如果 Java 在 Docker 网络中，可写服务名如 `business-api:8080`。
- 如果应用不在同机，必须限制 8080 只允许 Nginx 所在地址访问。

不要把 Python 8000、MinIO 9000/9001、Qdrant、数据库或 Redis 加入公网 Nginx location。

## 6. 首次发布

先验证 Java 健康接口（具体路径由后端实现确定；推荐只允许本机访问 `/actuator/health/readiness`）：

```bash
curl --fail --silent http://127.0.0.1:8080/actuator/health/readiness
```

创建当前版本软链接：

```bash
sudo ln -sfn "/srv/xinchuang/frontend/releases/$RELEASE_ID" /srv/xinchuang/frontend/current
```

验证 Nginx 配置后再平滑加载：

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl is-active nginx
```

任何一步失败都停止，不要继续。先修复错误并重新执行 `nginx -t`。

## 7. Nginx 和静态路由验证

将示例域名替换为真实域名：

```bash
curl -I http://support.example.com/
curl -I https://support.example.com/
curl -I https://support.example.com/chat
curl -I https://support.example.com/tickets/WO-NOT-EXIST
curl -I https://support.example.com/internal/ai/v1/chat/stream
curl -I https://support.example.com/actuator/health
```

预期：

- HTTP 返回 301 到 HTTPS。
- `/`、`/chat`、`/tickets/...` 返回前端 `index.html`，刷新不出现 Nginx 404。
- `/assets/*` 有长期缓存；`index.html` 为 no-cache。
- `/internal/**` 和 `/actuator/**` 对公网返回 404。
- HTTPS 证书链、域名和有效期正确。

## 8. API 冒烟测试

### 8.1 登录

```bash
curl -i -c cookies.txt -H "Content-Type: application/json" \
  -d '{"mode":"password","account":"TEST_ACCOUNT","password":"TEST_PASSWORD","rememberDevice":false}' \
  https://support.example.com/api/v1/auth/login
```

从响应 JSON 提取 `accessToken`，仅在当前终端临时设置，不写进脚本或仓库：

```bash
export ACCESS_TOKEN='替换为测试 token'
```

检查响应有 `requestId,data.accessToken,data.expiresAt,data.user`；Cookie 包含 `Secure,HttpOnly,SameSite`；用户手机号已脱敏。

### 8.2 普通查询和越权

```bash
curl --fail -H "Authorization: Bearer $ACCESS_TOKEN" \
  "https://support.example.com/api/v1/sessions?page=1&pageSize=20"
curl --fail -H "Authorization: Bearer $ACCESS_TOKEN" \
  "https://support.example.com/api/v1/faq?page=1&pageSize=20"
curl --fail -H "Authorization: Bearer $ACCESS_TOKEN" \
  "https://support.example.com/api/v1/tickets?page=1&pageSize=20"
```

再用不存在或属于其他用户的资源 ID 请求详情，预期统一 404，不泄露所有者信息。

### 8.3 SSE

```bash
curl -N --no-buffer \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Accept: text/event-stream" \
  -H "Content-Type: application/json" \
  -d '{"sessionId":3,"message":"统信 UOS 打印机驱动安装失败怎么办？"}' \
  https://support.example.com/api/v1/chat/stream
```

确认数据逐段到达，不是结束后一次性出现；第一个事件 `meta`；`sequence` 严格递增；最后只有一个 `done` 或 `error`；响应头含 `text/event-stream`、`X-Accel-Buffering: no`。记录 `requestId` 后调用状态接口，并核对数据库最终状态。

取消测试：发起一个长回答，收到 `meta` 后中断 curl，再调用：

```bash
curl -X POST \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  "https://support.example.com/api/v1/chat/requests/21/cancel"
```

预期下游模型停止，状态最终为 `CANCELLED` 或 `INTERRUPTED`，未完成文本不出现在下一轮上下文。

### 8.4 附件和工单

```bash
curl --fail \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Idempotency-Key: smoke-attachment-20260825-0001" \
  -F "file=@allowed-test.log;type=text/plain" \
  https://support.example.com/api/v1/ticket-attachments
```

取出 `attachmentId` 创建工单：

```bash
curl --fail \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: smoke-ticket-20260825-0001" \
  -d '{"title":"部署冒烟测试工单","category":"其他","deviceBrand":"测试品牌","deviceModel":"TEST-01","description":"用于验证动态工单和附件绑定流程。","contact":"13800138000","attachmentIds":["ATTACHMENT_ID"]}' \
  https://support.example.com/api/v1/tickets
```

验证附件下载 URL 只有工单所有者可获取、5 分钟后失效。再测试 50 MiB 超限、双扩展名、错误 MIME、恶意样本（只使用安全测试机构提供的标准样本）均被拒绝。

## 9. 浏览器端到端验收

使用无痕窗口并打开开发者工具：

1. 访问 `/chat`，未登录应跳到 `/login?redirect=/chat`。
2. 密码登录和短信登录各执行一次；刷新页面应通过 refresh cookie 恢复，不应看到 token 出现在 LocalStorage/SessionStorage。
3. 新会话第一次发送时请求体不含伪造 `sessionId`；收到 `meta` 后列表出现服务端真实会话 ID。
4. 连续发送问题，回答应增量显示、引用可见；停止按钮触发 cancel；赞踩发出 PUT 请求。
5. 重命名和删除会话，刷新后结果仍存在，证明不是仅改本地状态。
6. FAQ/手册关键词搜索应产生真实 GET 请求，断网时显示错误而非静默使用 mock。
7. 选择 1～5 个允许文件创建工单；网络面板应先上传附件，再用 `attachmentIds` 创建工单。
8. 工单列表、详情、回复、关闭、重开和附件下载逐项验证；刷新后状态不丢失。
9. 模拟 Access Token 过期，同时发多个请求；网络面板只能出现一个 refresh；失败后跳回登录。
10. 分别用 360、768、1280、1920 像素宽度检查响应式布局和键盘操作。

## 10. 安全和性能验收

- 以两个普通账号交叉访问会话、消息、工单和附件，全部返回 404/403。
- 普通用户 token 调 `/api/v1/admin/**` 必须 403；管理 token 不能调用用户身份接口混淆数据。
- 外部伪造 `X-Internal-*` 头，确认 Nginx 清空且内部路径仍 404。
- 检查登录、工单、附件和模型错误日志，无密码、完整手机号、Cookie、Bearer token、签名 URL、模型密钥或文档正文。
- 使用团队压测工具验收普通 API P95≤500ms；SSE 首字 P95≤5s；不要用生产真实账号和真实敏感附件压测。
- 断开 Python、Redis、MinIO 等依赖逐一验证稳定错误码和降级，不得返回堆栈或内部地址。
- 执行依赖、镜像、SAST、DAST 和 OpenAPI 破坏性变更检查。

## 11. 观察期

发布后至少观察 30 分钟：

- Nginx 4xx/5xx、499 和 upstream timeout。
- Java 错误率、P95、数据库连接池、Redis、附件失败率。
- SSE 活跃连接、首字时间、总时长、取消/断连和终止事件缺失。
- Python 模型 429/5xx、检索耗时、Qdrant 错误和 token/成本。
- 登录失败、refresh 重放、文件扫描拒绝和越权告警。

只有核心冒烟、错误率和安全检查均通过才结束观察期。

## 12. 回滚

发布前记录当前软链接：

```bash
readlink -f /srv/xinchuang/frontend/current
```

若仅前端异常，将软链接切回上一版本，然后验证并平滑加载：

```bash
sudo ln -sfn /srv/xinchuang/frontend/releases/PREVIOUS_RELEASE /srv/xinchuang/frontend/current
sudo nginx -t
sudo systemctl reload nginx
```

清浏览器强缓存通常不需要，因为 `index.html` 不缓存、资源带 hash。若 API 契约已发生不兼容变更，必须同时按后端发布方案回滚；不得只回滚前端后继续运行不兼容 API。

回滚后重复第 7、8 节核心检查，并保存失败时间、requestId、版本号和影响范围。不要删除失败版本，保留到复盘和审计完成。
