# 信创智能客服系统接口文档

版本：v1.0  
契约日期：2026-08-25  
公共基地址：`/api/v1`  
机器可读契约：同目录 `openapi.yaml`、`sse-events.schema.json`

## 1. 适用范围

本文档独立定义用户 Web 端、管理端、Java 业务服务、Python AI 服务之间的接口。当前仓库中的 `frontend` 已直接对接“用户端接口”；管理端和内部接口是后端实现必须遵守的契约，不允许由浏览器直接调用内部接口。

## 2. 通用协议

### 2.1 请求头

| 请求头 | 必填条件 | 说明 |
|---|---|---|
| `Authorization: Bearer <token>` | 除登录、短信和 refresh 外 | Access Token；用户端与管理端 audience 不同 |
| `X-Request-Id` | 建议 | UUID/ULID；缺失时由网关生成 |
| `Idempotency-Key` | 表中标记“是”的写接口 | 16～128 字符，同一调用方和接口内唯一 |
| `Content-Type` | 有请求体时 | JSON 为 `application/json`；上传为 `multipart/form-data` |
| `Accept: text/event-stream` | 流式问答 | POST SSE |
| `If-Match` | 管理端更新资源 | 资源版本，例如 `"12"` |

Access Token 由登录或刷新接口返回，前端应只保存在浏览器内存。Refresh Token 只通过 `HttpOnly; SameSite=Lax; Path=/api/v1/auth` Cookie 传递；本地 HTTP 练习环境默认 `Secure=false`，HTTPS 部署时通过配置改为 `true`。当前实现不下发或校验 XSRF Cookie/Header。

### 2.2 成功响应

```json
{
  "requestId": "01K3...",
  "data": {}
}
```

分页 `data` 固定为：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20
}
```

### 2.3 错误响应

错误采用 RFC 7807 风格并使用真实 HTTP 状态码：

```json
{
  "type": "https://support.example.com/problems/validation-failed",
  "title": "请求参数不正确",
  "status": 400,
  "code": "VALIDATION_FAILED",
  "detail": "请检查标记字段",
  "requestId": "01K3...",
  "errors": [{ "field": "message", "message": "长度必须为 1～8000" }]
}
```

通用状态：`400` 参数错误、`401` 未登录或 token 过期、`403` 无权限、`404` 不存在或无权查看、`409` 幂等/版本/状态冲突、`413` 文件过大、`415` 文件类型不支持、`422` 业务校验失败、`429` 限流、`503` 依赖不可用。

### 3.2 认证

发送短信：

```json
POST /auth/sms-codes
{ "phone": "13800138000" }
```

无论手机号是否注册都返回 `204`。验证码由后端随机生成并打印到开发环境控制台，在 Redis database 3 中保存 5 分钟；重复发送会覆盖旧验证码并重置有效期，不限制重发间隔。验证码只有在校验成功后才删除。

密码登录：

```json
POST /auth/login
{ "mode": "password", "account": "demo", "password": "***", "rememberDevice": true }
```

短信登录：

```json
{ "mode": "sms", "phone": "13800138000", "code": "123456", "rememberDevice": true }
```

登录和 refresh 的 `data` 相同：

```json
{
  "accessToken": "eyJ...",
  "expiresAt": "2026-08-25T02:30:00Z",
  "user": { "id": "usr_...", "name": "张三", "phone": "138****8000", "avatarText": "张" }
}
```

Access Token 为 HS256 JWT，有效期 2 小时，通过 `Authorization: Bearer <token>` 访问后续用户接口。Refresh Token 有效期 30 天，只通过名为 `XC_REFRESH_TOKEN` 的 HttpOnly、SameSite=Lax Cookie 传递，数据库仅保存其 SHA-256 摘要；每次 refresh 都会撤销旧 token 并返回新 Cookie。`rememberDevice=true` 时 Cookie 持久化 30 天，否则为浏览器会话 Cookie。logout 使用 Refresh Cookie 撤销当前登录设备并返回 `204`。

密码登录时，账号不存在返回 `AUTH_USER_NOT_FOUND`；密码错误返回 `AUTH_BAD_CREDENTIALS`。短信登录时，用户不存在会自动创建系统账号；验证码错误或过期返回 `AUTH_SMS_CODE_INVALID`。用户状态为 `DISABLED` 或 `LOCKED` 时返回 `AUTH_USER_DISABLED`。

### 3.3 会话和消息

`GET /sessions?page=1&pageSize=20&keyword=打印机` 返回 `ChatSession[]`。字段为 `id,title,preview,updatedAt`。列表按 `updatedAt` 降序。

`GET /sessions/{id}/messages?page=1&pageSize=50` 返回 `ChatMessage[]`。字段为 `id,requestId,role,content,status,createdAt,stage,citations,feedback`。只返回完整消息；中断片段不得作为后续上下文。

重命名请求：`{ "title": "统信 UOS 打印机问题" }`，标题 1～30 字符。删除成功返回 `204`。资源不属于当前用户时统一返回 `404`。

反馈请求：

```json
PUT /messages/12/feedback
{ "feedback": "up" }
```

`feedback` 可为 `up`、`down` 或 `null`；`null` 表示清除。

### 3.4 POST SSE 问答

请求：

```json
{
  "sessionId": 3,
  "message": "统信 UOS 打印机驱动安装失败怎么办？"
}
```

首次对话必须省略 `sessionId`，由服务端创建记录并在 `meta` 事件返回 MySQL 自增主键。`message` 长度 1～8000。

SSE 示例：

```text
id: 1
event: meta
data: {"event":"meta","requestId":21,"sequence":1,"occurredAt":"2026-08-25T02:00:00Z","payload":{"sessionId":3,"userMessageId":11,"assistantMessageId":12}}

id: 2
event: status
data: {"event":"status","requestId":21,"sequence":2,"occurredAt":"2026-08-25T02:00:00Z","payload":{"stage":"retrieval","message":"正在检索知识库"}}

id: 3
event: delta
data: {"event":"delta","requestId":21,"sequence":3,"occurredAt":"2026-08-25T02:00:01Z","payload":{"content":"请先确认系统版本。"}}

id: 4
event: done
data: {"event":"done","requestId":21,"sequence":4,"occurredAt":"2026-08-25T02:00:02Z","payload":{"finishReason":"stop","messageId":12}}

```

规则：`sequence` 严格递增；首个业务事件必须为 `meta`；最后只能有一个 `done` 或 `error`；空闲时每 15 秒发送 `heartbeat`；总时长默认不超过 120 秒。事件 JSON 必须包含与 SSE `event:` 相同的 `event` 字段。

客户端取消时先中止读取，再调用 `/chat/requests/{requestId}/cancel`。取消接口返回当前状态；已进入终态时仍返回 `200`。

状态查询 `data`：

```json
{
  "status": "SUCCEEDED",
  "sessionId": 3,
  "assistantMessageId": 12,
  "answer": "请先确认系统版本。",
  "citations": [],
  "error": null,
  "startedAt": "2026-08-25T02:00:00Z",
  "finishedAt": "2026-08-25T02:00:02Z"
}
```

状态只允许 `ACCEPTED/RUNNING/SUCCEEDED/FAILED/CANCELLED/INTERRUPTED`；非 `SUCCEEDED` 不返回 `answer`。

### 3.5 FAQ 和手册

`GET /faq/categories` 返回 `{id,name,sortOrder}`；`GET /faq` 和 `/manuals` 支持 `keyword,categoryId,page,pageSize`。列表项统一为 `id,kind,title,summary,category,updatedAt`，FAQ 可附带 `question,hotCount`。

`GET /faq/{faqId}` 只返回已发布且所属分类启用的 FAQ，字段为
`id,categoryId,categoryName,title,question,answer,summary,hotCount,updatedAt`。详情首先读取
Java 业务 Redis 的 `detail:{faqId}`，未命中时查询 MySQL 并按现有 TTL 回填。管理端 FAQ
或分类事务提交成功后统一删除分类、列表和详情缓存，由下一次用户查询重建。

下载地址响应为 `{ "url": "https://...", "expiresAt": "..." }`。URL 默认 5 分钟有效，不得记录到普通日志或长期缓存。

### 3.6 工单与附件

附件上传为 `multipart/form-data`，字段名固定为 `file`。允许 `png,jpg,jpeg,pdf,txt,log,docx`，最多 5 个，单文件不超过 50 MiB。服务端先计算 SHA-256 并进入隔离区；扫描失败返回 `422 FILE_SCAN_REJECTED`。

上传响应：

```json
{
  "id": "att_...",
  "fileName": "driver-install.log",
  "size": 18240,
  "contentType": "text/plain"
}
```

临时附件 24 小时内未绑定工单应自动清理。创建工单：

```json
{
  "title": "统信 UOS 打印机驱动安装失败",
  "category": "驱动问题",
  "deviceBrand": "长城",
  "deviceModel": "世恒 TD120A2",
  "description": "安装官方驱动后仍无法识别……",
  "contact": "13800138000",
  "attachmentIds": ["att_..."]
}
```

工单字段为 `id,title,category,deviceBrand,deviceModel,description,contact,status,assignee,createdAt,updatedAt,attachments,replies,timeline`。状态只允许 `PENDING/PROCESSING/WAITING_USER/RESOLVED/CLOSED`。

回复请求为 `{ "content": "系统版本为 UOS 1070" }`。关闭请求体为空。重开请求为 `{ "reason": "问题再次出现" }`；只有本人、状态为 `RESOLVED` 且解决后不超过 7 天可以重开。

## 4. 管理端接口

管理接口位于 `/api/v1/admin`，必须使用 admin audience 的 JWT 和 RBAC。当前本机练习版本采用账号密码单步登录，不启用 MFA；查询支持分页，资源更新要求 `If-Match`，冲突返回 `409 RESOURCE_VERSION_CONFLICT`。

### 4.1 认证与 IAM

| 方法和路径 | 请求核心字段 | 响应/说明 |
|---|---|---|
| `POST /auth/login` | `account,password` | 直接返回管理 Access JWT，并设置独立 Refresh Cookie |
| `POST /auth/refresh` | Cookie | 轮换管理 refresh token |
| `POST /auth/logout` | 空 | 注销当前管理设备 |
| `GET /admins` | `keyword,role,status,page,pageSize` | 管理员只读列表；账号由开发 SQL 维护 |

### 4.2 工单

| 方法和路径 | 请求核心字段 | 结果 |
|---|---|---|
| `GET /tickets` | `keyword,status,assigneeId,from,to,page,pageSize` | 全部工单分页 |
| `GET /tickets/{id}` | — | 完整详情与审计时间线 |
| `POST /tickets/{id}/assign` | `assigneeId` | `PENDING→PROCESSING` |
| `POST /tickets/{id}/replies` | `content,attachmentIds[]` | 管理员回复 |
| `POST /tickets/{id}/transitions` | `targetStatus,reason` | 按状态机迁移 |
| `POST /tickets/{id}/convert-to-faq` | `categoryId,title,question,answer` | 创建 FAQ 草稿并返回 ID |

### 4.3 FAQ、手册与知识库

| 资源 | 接口 |
|---|---|
| FAQ 分类 | `GET/POST /faq-categories`；`PATCH/DELETE /faq-categories/{id}`；`PUT /faq-categories/order` |
| FAQ | `GET/POST /faqs`；`GET/PATCH /faqs/{id}`；`POST /faqs/{id}/publish`；`POST /faqs/{id}/archive` |
| 手册分类 | `GET/POST /manual-categories`；`PATCH/DELETE /manual-categories/{id}` |
| 手册 | `GET /manuals`；multipart `POST /manuals`；`GET/PATCH /manuals/{id}`；multipart `POST /manuals/{id}/versions`；`POST /manuals/{id}/publish`；`POST /manuals/{id}/archive`；`GET /manuals/{id}/file` |

维修手册上传只接受 PDF、DOCX、TXT、MD；旧版二进制 DOC 返回
`415 MANUAL_FILE_TYPE_UNSUPPORTED`。Java 的已发布清单和共享目录原文件是 RAG 真相源。

内容版本字段固定包含 `id,resourceId,version,status,content,createdBy,createdAt,publishedAt`。状态为 `DRAFT/IN_REVIEW/PUBLISHED/ARCHIVED`。发布、下架和重试必须填写 `reason` 并写审计。

## 5. Java → Python AI 内部接口

基地址 `/internal/ai/v1`，仅专用网络可达。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/chat/stream` | HMAC 鉴权的内部 SSE |
| POST | `/chat/requests/{requestId}/cancel` | 幂等取消 |
| POST | `/evaluations/try` | 管理端试问，返回路由与召回明细 |

流式请求：

```json
{
  "requestId": 21,
  "sessionId": 3,
  "userId": 8,
  "message": "打印机驱动安装失败",
  "history": [{ "role": "user", "content": "..." }],
  "policy": {
    "modelRoute": "customer-service-default",
    "knowledgeBaseIds": ["kb_..."],
    "toolsEnabled": false,
    "maxOutputTokens": 1200
  }
}
```

浏览器不得传 `modelRoute`、模型 ID、工具白名单或知识库 ID。

## 6. Python → Java RAG 清单接口

`GET /internal/rag/v1/manuals` 使用 `X-Internal-Token`，只返回已发布、分类启用、未删除且
格式受支持的手册。字段固定为
`sourceId,documentId,title,summary,objectKey,fileName,contentType,sha256,versionNo,resourceVersion`。
开发环境 Java Token 为空时允许本机联调；部署环境两个进程必须配置相同的随机长 Token，
并限制该路径仅内网可达。

Agent 每次进入 RAG 分支时读取清单，在进程内同步锁下增量更新自己的 Chroma。清单不可用
时本轮不得查询旧 Chroma。Java 不写 Chroma，FAQ Redis 和 Agent Redis 也都不保存索引状态。

## 7. 两套 Redis 边界

- Java `spring.data.redis` / `REDIS_*`：登录状态、验证码和 FAQ cache-aside；
- Python `AGENT_REDIS_URL`：LangGraph checkpoint、会话锁和上下文归档 Stream。

二者是独立服务、连接和数据空间，不允许通过复用 URL 或 Key 前缀合并。

## 8. 核心业务错误码

| code | HTTP | 场景 |
|---|---:|---|
| `AUTH_USER_NOT_FOUND` | 404 | 密码登录账号不存在 |
| `AUTH_BAD_CREDENTIALS` | 401 | 密码错误 |
| `AUTH_SMS_CODE_INVALID` | 401 | 验证码错误或过期 |
| `AUTH_USER_DISABLED` | 403 | 用户被停用或锁定 |
| `AUTH_TOKEN_MISSING` | 401 | 未提供 Access Token |
| `AUTH_TOKEN_INVALID` | 401 | Access Token 格式或签名无效 |
| `AUTH_TOKEN_EXPIRED` | 401 | Access Token 过期 |
| `AUTH_REFRESH_INVALID` | 401 | refresh token 不存在、过期或已撤销 |
| `AUTH_REFRESH_REPLAYED` | 401 | refresh token 被重复使用 |
| `VALIDATION_FAILED` | 400 | 字段校验失败 |
| `RESOURCE_NOT_FOUND` | 404 | 不存在或无权访问 |
| `IDEMPOTENCY_KEY_CONFLICT` | 409 | 同键不同请求体 |
